해당 포스팅은 인프런의 IntelliJ를 시작하시는 분들을 위한 IntelliJ 가이드 강의를 참조하여 작성한 글입니다.

들어가며

이전 편에서 우리는 코드를 복사하고, 삭제하고, 옮기는 단축키들을 배웠다. 그런데 그 모든 단축키에는 숨은 전제가 하나 있었다. 바로 "커서가 이미 원하는 위치에 가 있다" 는 것이다.

생각해보면 우리가 코딩할 때 실제로 하는 일의 상당 부분은 타이핑이 아니라 이동이다. 이 줄에서 저 줄로, 이 단어에서 저 단어로, 이 파일에서 저 파일로. 그리고 대부분의 사람들은 이 이동을 마우스로 처리한다. 강사님도 이 부분을 이렇게 짚는다.

"마우스를 이용하는 것은 생산성에 좋지 않습니다."

"하지만 그렇다고 이제 화살표를 한 칸씩 이동하면서 이동하기에는 너무 힘들죠?"

정확히 이 두 문장 사이에 이번 편의 주제가 있다. 마우스도 쓰기 싫고, 방향키를 수십 번 누르기도 싫다면 어떻게 해야 할까? 답은 더 큰 단위로 점프하는 것이다. 한 글자씩이 아니라 단어 단위로, 줄 단위로, 문법 구조 단위로, 그리고 파일 단위로 말이다.

이번 편에서 다룰 내용을 미리 정리하면 다음과 같다.

  1. 포커스 에디터: 에디터 안에서 커서를 큰 단위로 옮기고 선택하는 방법
  2. 포커스 특수키: 문법 단위 선택, 이동 히스토리, 멀티 커서, 오류 이동
  3. 에디터와 도구 창 사이 이동: 코드 창과 좌측 파일 트리·터미널 사이를 마우스 없이 오가는 방법

참고로 앞으로 계속 나올 캐럿 (Caret) 이라는 단어는 우리가 흔히 "커서"라고 부르는 그 깜빡이는 세로 막대를 말한다. IntelliJ 공식 문서와 설정 화면에서는 캐럿이라는 표현을 쓰기 때문에, 나중에 설정을 검색할 때를 위해 알아두면 좋다.

포커스 에디터

이번에는 포커스 관련 단축키를 알아보도록 하겠다. 아래의 코드를 가지고 한번 알아보자.

package me.sungbin.chap2;

public class FocusEditor {

    public void page2() {

    }

    public void page3() {

page1부터 page8까지 의미 없는 메서드가 잔뜩 있는 이유는, 뒤에서 다룰 Page Up/Down을 실습하려면 화면을 넘길 만큼 코드가 길어야 하기 때문이다.

단어 별 이동

만약 커서가 맨 앞에 있는데 이것을 가운데로 빠르게 가고 싶은 상황이 있을 것이다. 이런 경우 우리는 마우스를 이용하거나 좌/우 방향키로 일일이 한땀한땀 이동 할 것이다. 하지만 이것은 매우 비효율적인 방식이다. 따라서 이것을 편하게 하기 위해 단축키를 제공해준다. 맥 기준으로 option + 좌/우 방향키이고, 윈도우/리눅스 기준으로는 Ctrl + 좌/우 방향키이다.

이 단축키를 누르면 한 글자가 아니라 단어 하나를 통째로 건너뛴다. 위 예제의 String s = "안녕하세요..." 라인에서 맨 앞부터 눌러보면 String → s → = → " 순서로 툭툭 점프하는 것을 볼 수 있다.

[꿀팁] CamelHumps를 켜면 이 단축키가 훨씬 강력해진다

자바 코드에서 우리가 만나는 식별자는 대부분 getUserName, EmailSenderService처럼 카멜 케이스다. 그런데 기본 설정에서는 getUserName 전체가 한 단어로 취급되기 때문에, 여기서 Name만 고치고 싶어도 단어 이동이 도움이 되지 않는다.

이때 켜면 좋은 설정이 CamelHumps다.

  • 경로: Settings → Editor → General → Smart Keys → Use CamelHumps words 체크

이걸 켜면 IntelliJ가 getUserName을 get / User / Name 세 단어로 인식한다. 그 결과 아래 동작이 전부 대문자 경계를 기준으로 바뀐다.

  • 단어 단위 이동 (option/Ctrl + ←/→)
  • 단어 단위 선택 (option/Ctrl + Shift + ←/→)
  • 단어 단위 삭제 (option/Ctrl + Backspace)

즉 getUserName에서 Name만 정확히 선택해서 Email로 바꾸는 일이 훨씬 쉬워진다. 필자는 이 설정을 켜두는 것을 강력하게 추천한다. 자바나 코틀린처럼 카멜 케이스를 쓰는 언어에서는 체감 효과가 상당히 크다.

단어 별 선택

위의 단축키를 이용해서 단어별로 선택해서 하고 싶은 경우도 있을 것이다. 물론 마우스로 드래그를 해도 되지만 마우스를 이용하면 생산성이 떨어진다. 따라서, 이것도 인텔리제이에서 단축키를 제공해주는데 맥 기준 option + shift + 좌/우 방향키이고, 윈도우/리눅스 기준 Ctrl + Shift + 좌/우 방향키이다.

여기서 하나의 원리를 발견할 수 있는데, 강사님도 이 부분을 이렇게 언급한다.

"보통 우리가 이렇게 셀렉트 하는 거는 쉬프트 키를 누르면 된다라고 대부분 다 인식하고 계세요."

즉 "이동 단축키 + Shift = 이동한 만큼 선택" 이라는 아주 단순한 규칙이다. 이 규칙은 이번 편에 나오는 거의 모든 이동 단축키에 그대로 적용된다.

이동 선택
option + ←/→ (단어 이동) option + shift + ←/→ (단어 선택)
command + ←/→ (라인 처음/끝) command + shift + ←/→ (라인 처음/끝까지 선택)
Fn + ↑/↓ (페이지 이동) Fn + shift + ↑/↓ (한 페이지 선택)

그러니 이 절의 단축키들은 사실상 외울 개수가 절반이다. 이동만 익히고 Shift를 얹으면 된다.

라인 첫/끝 이동

문장 중간에 커서가 있는데 그 줄의 맨 앞이나 맨 끝으로 가고 싶은 경우가 있다. 예를 들어 지금 줄 다음에 새 코드를 쓰고 싶다면 줄 맨 끝으로 가서 엔터를 쳐야 한다. 이때도 마우스로 클릭하면 생산성이 떨어지니 단축키를 쓰자.

  • 맥: command + 좌/우 방향키 (또는 Fn + 좌/우 방향키)
  • 윈도우/리눅스: Home / End

맥에서 왜 Fn을 누르는가?

윈도우 키보드에는 Home과 End라는 물리적인 키가 따로 있다. 그런데 맥북 키보드에는 이 키들이 없다. 그래서 macOS는 Fn + ←를 Home으로, Fn + →를 End로 대체 입력하도록 만들어두었다.

즉 맥에서는 두 가지 방법이 모두 동작한다.

  • command + ←/→: IntelliJ 기본 키맵에 정식으로 등록된 단축키 (Move Caret to Line Start / End)
  • Fn + ←/→: macOS가 Home/End 키를 흉내 내주는 방식

참고로 맥에서 풀사이즈 외장 키보드를 쓴다면 Home/End 키가 물리적으로 있으므로 그대로 쓰면 된다.

하나 더 알아두면 좋은 것은, macOS에는 터미널에서 유래한 Ctrl + A(줄 맨 앞) / Ctrl + E(줄 맨 끝)라는 시스템 단축키도 있다는 점이다. 다만 IntelliJ에서는 다른 기능과 겹칠 수 있으니 참고만 하자.

그리고 실제로 눌러보면 재미있는 동작을 하나 발견할 수 있다. 들여쓰기가 있는 코드에서 라인 맨 앞으로 가는 단축키를 누르면, 첫 번째로는 들여쓰기를 제외한 코드의 시작 위치로 가고, 한 번 더 누르면 진짜 줄의 맨 앞 (0번째 칸) 으로 간다. 대부분의 경우 우리가 원하는 것은 전자이기 때문에 아주 편리한 동작이다.

라인 전체 선택

위의 단축키를 응용한 버전으로 라인 전체를 선택하는 단축키도 인텔리제이에서 제공해준다.

  • 맥: command + shift + 좌/우 방향키 (또는 Fn + shift + 좌/우 방향키)
  • 윈도우/리눅스: Shift + Home / Shift + End

앞서 말한 "이동 + Shift" 규칙이 그대로 적용된 것이다. 커서 위치에서 줄 끝까지 선택하고 싶으면 오른쪽, 줄 처음까지 선택하고 싶으면 왼쪽을 누르면 된다.

참고로 이전 편에서 배운 라인 복사 (command/Ctrl + d) 나 라인 삭제 (command + backspace / Ctrl + y) 는 굳이 선택하지 않아도 줄 전체에 동작한다. 그러니 "복사하려고 줄 전체를 선택"할 필요는 없다. 이 선택 단축키는 줄의 일부만 잘라내거나 옮길 때 쓰는 것이라고 이해하면 정확하다.

Page up / Page down

첫 라인에서 우리는 아래 메서드를 찾고 싶어서 이동해야할 때가 있다. 그러면 우리는 마우스 휠을 이용해서 확인하거나 키보드로 한땀 한땀 이동할 것이지만 매우 비효율적이다. 이를 위해 인텔리제이에서 단축키를 제공한다.

  • 윈도우/리눅스: Page Up / Page Down
  • 맥: Fn + 위/아래 방향키

여기서도 맥의 사정은 앞과 똑같다. 강사님의 말을 그대로 빌리면 이렇다.

"맥을 사용하시는 분들은 보통 이 키보드에 페이지 업다운이 없어요."

그래서 맥북에서는 Fn + ↑가 Page Up, Fn + ↓가 Page Down 역할을 한다.

한 번 누를 때 얼마나 이동하는지 궁금할 텐데, 강의 기준으로 약 25~30줄 정도씩 움직인다. 정확히는 "현재 에디터 창에 보이는 만큼"이라서 화면 크기나 폰트 크기에 따라 달라진다.

[추가] 파일의 처음과 끝으로 한 번에 가기

페이지 단위보다 더 크게 점프하고 싶다면, 즉 파일의 맨 위나 맨 아래로 바로 가고 싶다면 아래 단축키를 쓰면 된다.

  • 맥: command + ↑ (파일 처음) / command + ↓ (파일 끝)
  • 윈도우/리눅스: Ctrl + Home / Ctrl + End

여기에도 Shift 규칙이 적용되므로, command + shift + ↑를 누르면 커서 위치부터 파일 처음까지 전부 선택된다. 파일 전체를 선택하는 command/Ctrl + a와 함께 알아두면 유용하다.

그러면 단축키들을 정리해보자.

  • 단어별 이동
    • 맥: option + 좌/우 방향키
    • 윈도우/리눅스: Ctrl + 좌/우 방향키
  • 단어별 선택
    • 맥: option + shift + 좌/우 방향키
    • 윈도우/리눅스: Ctrl + Shift + 좌/우 방향키
  • 라인 첫/끝 이동
    • 맥: command + 좌/우 방향키, Fn + 좌/우 방향키
    • 윈도우/리눅스: Home, End
  • 라인 전체 선택
    • 맥: command + shift + 좌/우 방향키, Fn + shift + 좌/우 방향키
    • 윈도우/리눅스: Shift + Home / Shift + End
  • Page up / down
    • 맥: Fn + 위/아래 방향키
    • 윈도우/리눅스: Page Up / Page Down
  • 파일 처음/끝 이동
    • 맥: command + 위/아래 방향키
    • 윈도우/리눅스: Ctrl + Home / Ctrl + End

포커스 특수키

강사님은 이 챕터를 시작하면서 다룰 내용을 이렇게 예고한다.

"첫 번째는 포커스 범위를 한 단계씩 늘리는 것, 두 번째는 포커스를 뒤로 앞으로 가는 기능, 세 번째는 포커스를 여러 개를 한 번에 잡는 멀티 포커스, 네 번째는 오류 라인으로 자동으로 포커스가 가는 기능까지 총 4가지를 진행할 예정입니다."

앞 절이 "단어·줄 같은 물리적 단위"로 움직이는 이야기였다면, 이번 절은 IDE가 코드의 의미를 이해하고 있기 때문에 가능한 기능들이다. 여기서부터가 진짜 IDE다운 부분이라고 볼 수 있다.

포커스 범위 한 단계씩 늘리기

해당 단축키는 은근 유용하다. 어떤 범위를 선택할 때 유용하게 사용되는데 맥 기준 option + 위/아래 방향키이고, 윈도우/리눅스 기준으로는 Ctrl + w(확장) / Ctrl + Shift + w (축소)이다.

이 기능의 정식 명칭은 Extend Selection / Shrink Selection이다. 여기서 중요한 것은 이 확장이 단순히 글자 수를 늘리는 것이 아니라 코드의 문법 구조를 따라 확장된다는 점이다.

예를 들어 아래 코드에서 반갑습니다 부근에 커서를 두고 option + ↑를 계속 눌러보자.

System.out.println("안녕하세요. 반갑습니다. IntelliJ IDEA Ultimate");

그러면 대략 아래 순서로 선택 범위가 커진다.

  1. 반갑습니다 — 단어
  2. 안녕하세요. 반갑습니다. IntelliJ IDEA Ultimate — 따옴표 안의 문자열 내용
  3. "안녕하세요. 반갑습니다. IntelliJ IDEA Ultimate" — 따옴표를 포함한 문자열 리터럴
  4. System.out.println("...") — 메서드 호출 전체
  5. System.out.println("..."); — 세미콜론을 포함한 문장
  6. 메서드 블록 전체 → 클래스 전체

반대로 option + ↓를 누르면 한 단계씩 다시 좁아진다. 강사님의 표현을 빌리면 이렇다.

"이 옵션 위로 가는 화살표를 사용하시면 포커스가 예를 기준으로 연관된 것만 먼저 선택되기 때문에, 우리가 원하는 범위까지만 바로 찾아내서 잘라내거나 복사할 수가 있습니다."

이게 왜 강력하냐면, 마우스로 드래그할 때는 괄호나 따옴표를 하나 빼먹거나 더 잡는 실수가 정말 자주 발생하기 때문이다. 특히 아래처럼 중첩된 코드에서는 손으로 정확히 잡는 게 거의 불가능하다.

List<String> result = names.stream()
        .filter(name -> name.startsWith("s"))
        .map(name -> name.toUpperCase())
        .collect(Collectors.toList());

여기서 .filter(...) 한 줄만 정확히 선택하고 싶을 때, 람다식 안 어딘가에 커서를 두고 option + ↑를 두어 번 누르면 괄호 짝이 정확히 맞는 상태로 선택된다. 그 상태에서 잘라내거나 지우면 문법이 깨지지 않는다.

이 기능은 다음 편에서 다룰 리팩토링과 함께 쓰면 진가를 발휘한다. 어떤 표현식을 변수로 뽑아내고 싶을 때, 먼저 option + ↑로 정확한 범위를 잡고 리팩토링 단축키를 누르는 식이다.

포커스 뒤로/앞으로 가기

우리가 어떤 것을 작성할 때 뒤로가기나 앞으로 가기를 유용하게 사용하는 것처럼 포커스도 이전 포커스로 이동하는 것이 가능하다. 해당 기능은 단일 파일뿐만 아니라 여러 파일에서 사용이 가능하다. 예를 들어 A라는 파일에 포커스를 두었다가 B라는 파일에 포커스가 갔고 해당 단축키를 통해 이전 포커스로 이동하려고 한다면 A 파일에 포커스로 이동이 가능하다는 것이다.

  • 맥: command + [ (뒤로) / command + ] (앞으로)
  • 윈도우/리눅스: Ctrl + Alt + 좌/우 방향키

강사님은 이 기능을 되돌리기에 빗대어 설명한다.

"이것과 비슷하게 포커스도 이전 포커스와 그 이후의 포커스를 마음대로 왔다 갔다 할 수 있는 단축키가 있습니다."

이 기능이 진짜 빛나는 순간은 코드를 따라 들어갔다가 돌아올 때다. 이전 편에서 배운 command + b(선언부로 이동)로 메서드를 타고 들어가다 보면 어느 순간 "내가 원래 어디서 출발했더라?" 하는 상황이 생긴다. 이때 command + [를 몇 번 누르면 왔던 길을 그대로 되짚어 돌아온다. 브라우저의 뒤로 가기와 완전히 같은 감각이다.

[강력 추천] 마지막으로 편집한 위치로 돌아가기

강의에는 나오지 않지만, 필자가 개인적으로 Back보다 더 자주 쓰는 단축키가 있다.

  • 맥: command + shift + backspace
  • 윈도우/리눅스: Ctrl + Shift + Backspace

이 단축키는 가장 최근에 코드를 수정한 위치로 바로 데려다준다. Back (command + [)이 "커서가 머물렀던 모든 위치"를 되짚는 것과 달리, 이건 실제로 타이핑한 자리만 기억한다.

그래서 이런 상황에 최적이다. 코드를 쓰다가 뭔가 확인하려고 여러 파일을 열어보며 한참 돌아다녔는데, 원래 작업하던 자리로 돌아가고 싶을 때. Back을 열 번 누르는 대신 이 단축키 한 번이면 된다. 여러 번 누르면 그 이전 편집 위치로 계속 거슬러 올라간다.

비슷한 계열로 최근 파일 목록을 띄우는 command + e(윈도우/리눅스 Ctrl + e)도 있다. 이건 다음 편인 검색에서 더 자세히 다룰 예정이다.

멀티 포커스

우리가 코드를 작성하다 보면 공통적으로 여러 라인을 같은 것으로 수정해야할 때가 있다. 특히 문자열 같은 곳에서 말이다. 이럴 때 우리는 멀티 포커스 기능을 사용하면 된다.

  • 맥: option을 두 번 누르되 두 번째는 누른 채로 위/아래 방향키
  • 윈도우/리눅스: Ctrl을 두 번 누르되 두 번째는 누른 채로 위/아래 방향키

이 조작법이 처음에는 잘 안 될 텐데, 정확히는 "탁-탁 (누른 채 유지) + 방향키" 리듬이다. 정식 명칭은 Clone Caret Above / Below이며, 말 그대로 커서를 위아래로 복제하는 기능이다.

강사님이 든 예시를 코드로 옮겨보면 이런 상황이다.

System.out.println(student1.getName());
System.out.println(student2.getName());
System.out.println(student3.getName());

여기서 세 줄의 getName을 전부 getCourse로 바꾸고 싶다면, 첫 줄의 getName에 커서를 두고 커서를 아래로 두 번 복제한 뒤 한 번만 타이핑하면 세 줄이 동시에 수정된다.

"그럴 때는 포커스가 여러 개면 되게 쉽게 해결될 것 같은 생각이 바로 들잖아요."

이 기능은 자바 코드뿐 아니라 SQL 쿼리, HTML, CSV 데이터처럼 같은 모양이 반복되는 텍스트를 다룰 때 특히 유용하다.

실무에서 더 많이 쓰는 멀티 커서 3종 세트

그런데 사실 위의 "커서 복제"는 줄마다 수정할 위치의 세로 좌표가 같을 때만 편하다. 실제 코드는 들쭉날쭉하기 때문에, 실무에서는 아래 방법들을 훨씬 많이 쓴다. 강의에는 없지만 함께 알아두면 좋다.

1. 같은 단어를 하나씩 추가 선택하기 (가장 많이 쓴다)

  • 맥: Ctrl + g
  • 윈도우/리눅스: Alt + j

커서를 어떤 단어에 두고 이 단축키를 누르면 그 단어가 선택되고, 계속 누를 때마다 아래쪽에 있는 같은 단어가 하나씩 추가로 선택된다. 원하는 만큼만 골라서 선택할 수 있다는 게 장점이다. 잘못 선택했다면 Ctrl + shift + g(윈도우/리눅스 Alt + shift + j)로 마지막 선택을 취소할 수 있다.

2. 같은 단어를 전부 선택하기

  • 맥: Ctrl + command + g
  • 윈도우/리눅스: Ctrl + Alt + Shift + j

현재 파일 안에 있는 같은 단어를 한 번에 전부 선택한다.

3. 마우스로 원하는 곳에 커서 찍기

  • 맥: option + shift + 클릭
  • 윈도우/리눅스: Alt + Shift + 클릭

이건 마우스를 쓰긴 하지만, 위치가 완전히 제각각일 때는 이게 가장 빠르다.

그리고 멀티 커서 상태를 해제하려면 Esc를 누르면 된다. 이건 반드시 기억해두자. 멀티 커서 상태인 줄 모르고 타이핑하면 엉뚱한 곳이 같이 수정되어 당황하게 된다.

[보너스] 세로로 네모나게 선택하기 (Column Selection Mode)

표 형태의 데이터나 정렬된 코드에서 특정 열만 잘라내고 싶을 때가 있다. 이때는 열 선택 모드를 켜면 된다.

  • 맥: command + shift + 8
  • 윈도우/리눅스: Alt + Shift + Insert

이 모드에서는 드래그가 사각형 영역으로 동작한다. 다시 같은 단축키를 누르면 일반 모드로 돌아온다.

⚠️ 주의: 멀티 커서로 이름을 바꾸지 말자

여기서 꼭 짚고 싶은 것이 있다. 멀티 커서는 텍스트를 바꾸는 기능이지 코드를 이해하고 바꾸는 기능이 아니다.

예를 들어 변수 이름 name을 userName으로 바꾸고 싶다고 해보자. 멀티 커서로 모든 name을 선택해서 바꾸면 어떻게 될까? 문자열 안의 "name"이나, 전혀 관계없는 다른 객체의 name 필드까지 같이 바뀌어버린다. 게다가 다른 파일에 있는 참조는 바뀌지 않는다.

그래서 이름을 바꾸는 작업은 반드시 리팩토링 기능 (Rename, shift + F6) 을 써야 한다. 이건 IDE가 코드의 의미를 이해하고 실제로 그 변수를 가리키는 곳만 정확히 바꿔주며, 프로젝트 전체의 다른 파일까지 반영해준다. 이 내용은 리팩토링 편에서 자세히 다룰 예정이다.

정리하면 이렇다.

  • 모양만 같은 텍스트를 반복 입력 → 멀티 커서
  • 의미가 같은 식별자의 이름 변경 → 리팩토링 Rename

오류 라인으로 자동 포커스

우리는 코드를 작성하다 보면 오류 라인으로 바로 이동하게끔 하고 싶은 경우가 있을 것이다. 인텔리제이는 해당 기능에 대한 단축키를 제공해주는데 맥/윈도우/리눅스 공통으로 F2이다.

이 기능의 좋은 점은 한 번 더 누르면 그 다음 오류로 계속 넘어간다는 것이다. 즉 오류가 세 개 있다면 F2를 누를 때마다 순서대로 이동하므로, 우측 스크롤바의 빨간 줄을 마우스로 찾아 클릭할 필요가 없다.

반대 방향으로 가고 싶다면 Shift + F2 를 누르면 이전 오류로 이동한다. 이건 강의에는 나오지 않지만 함께 기억해두면 좋다.

[실전 조합] F2 + option + Enter

오류 위치로 이동했다면 그 다음에 할 일은 당연히 고치는 것이다. 이때 IntelliJ의 만능키인 option + Enter(윈도우/리눅스 Alt + Enter)를 누르면 그 오류에 대한 해결책 목록이 나온다.

  • import가 빠졌다면 → import 추가
  • 타입이 안 맞다면 → 캐스팅 추가 또는 타입 변경
  • 메서드가 없다면 → 메서드 생성

그래서 실무에서는 F2 → option + Enter → Enter 라는 리듬으로 오류를 연속으로 처리하게 된다. 이 세 동작을 한 세트로 익혀두면 컴파일 에러 잡는 속도가 눈에 띄게 빨라진다.

참고로 option + Enter는 오류가 없을 때도 유용하다. 커서가 놓인 코드를 개선할 수 있는 제안 (Intention Action)을 보여주기 때문이다. 이 단축키는 앞으로도 계속 등장할 예정이다.

그러면 단축키를 정리해보자.

  • 포커스 범위 한 단계씩 늘리기/줄이기
    • 맥: option + 위/아래 방향키
    • 윈도우/리눅스
      • Ctrl + w (늘리기)
      • Ctrl + Shift + w (줄이기)
  • 포커스 뒤로/앞으로 가기
    • 맥: command + [, command + ]
    • 윈도우/리눅스: Ctrl + Alt + 좌/우 방향키
  • 마지막 편집 위치로 이동
    • 맥: command + shift + backspace
    • 윈도우/리눅스: Ctrl + Shift + Backspace
  • 멀티 포커스 (커서 복제)
    • 맥: option + option(누른 채) + 위/아래 방향키
    • 윈도우/리눅스: Ctrl + Ctrl(누른 채) + 위/아래 방향키
  • 같은 단어 하나씩 추가 선택
    • 맥: Ctrl + g
    • 윈도우/리눅스: Alt + j
  • 같은 단어 전부 선택
    • 맥: Ctrl + command + g
    • 윈도우/리눅스: Ctrl + Alt + Shift + j
  • 멀티 커서 해제
    • 맥/윈도우/리눅스: Esc
  • 오류 라인 자동 포커스
    • 다음 오류: F2
    • 이전 오류: Shift + F2
  • 빠른 수정 / 제안 보기
    • 맥: option + Enter
    • 윈도우/리눅스: Alt + Enter

에디터와 도구 창 사이의 포커스 이동

여기까지는 전부 에디터 안에서의 이야기였다. 그런데 실제 개발에서는 코드 창만 쓰는 게 아니다. 좌측의 파일 트리를 열어 파일을 찾고, 하단의 터미널에서 명령어를 치고, 실행 결과 창을 확인한다. 이 창들을 IntelliJ에서는 도구 창 (Tool Window) 이라고 부른다.

문제는 대부분의 사람이 이 창들 사이를 마우스로만 오간다는 것이다. 이전 편에서 command + n을 눌렀는데 원하는 메뉴가 안 나오는 이유가 "포커스가 에디터에 있어서"라고 설명했었는데, 그 문제를 해결하는 것이 바로 이 단축키들이다.

에디터로 돌아오기: Esc

가장 먼저 외워야 할 것은 이거다.

  • Esc: 어느 도구 창에 있든 에디터의 마지막 커서 위치로 복귀한다.

파일 트리에서 파일을 고르고 나서, 터미널에서 명령어를 치고 나서, 검색 결과를 보고 나서 — 무조건 Esc를 누르면 코드로 돌아온다. 이것만 익혀도 마우스 사용이 절반으로 줄어든다.

  • Shift + Esc: 현재 도구 창을 닫으면서 에디터로 돌아온다. 화면을 넓게 쓰고 싶을 때 유용하다.
  • F12: 반대로 마지막에 사용했던 도구 창으로 이동한다. Esc와 짝을 이루는 단축키다.

즉 F12로 나갔다가 Esc로 돌아오는 왕복을 키보드만으로 할 수 있다.

원하는 도구 창 바로 열기: 숫자 단축키

도구 창에는 각각 번호가 붙어 있다.

도구 창 맥 윈도우/리눅스 용도
Project command + 1 Alt + 1 좌측 파일 트리
Bookmarks command + 2 Alt + 2 북마크
Find command + 3 Alt + 3 검색 결과
Run command + 4 Alt + 4 실행 결과
Debug command + 5 Alt + 5 디버깅
Problems command + 6 Alt + 6 오류/경고 목록
Structure command + 7 Alt + 7 현재 파일의 구조
Terminal option + F12 Alt + F12 터미널

이 중에서 실무에서 가장 많이 쓰는 것은 command + 1(Project)과 option + F12(Terminal)다. 그리고 하나 더 추천하고 싶은 것은 command + 7( Structure) 인데, 현재 파일에 있는 필드와 메서드 목록을 트리로 보여주기 때문에 긴 클래스를 탐색할 때 아주 유용하다.

참고로 이미 열려 있는 도구 창의 단축키를 다시 누르면 창이 닫힌다. 즉 command + 1은 "Project 창 열기"가 아니라 "Project 창 토글"에 가깝다.

그리고 모든 도구 창을 한 번에 숨겨서 코드에만 집중하고 싶다면 command + shift + F12(윈도우/리눅스 Ctrl + Shift + F12)를 누르면 된다. 다시 누르면 원래 배치로 복원된다.

실전 워크플로우 예시

이 단축키들을 조합하면 아래와 같은 흐름을 마우스 없이 처리할 수 있다.

  1. command + 1 — 파일 트리로 이동
  2. 방향키로 파일 선택 후 Enter — 파일 열기 (포커스는 에디터로 이동)
  3. 코드 수정
  4. Ctrl + r — 실행 (이전 편에서 배웠다)
  5. command + 4 — 실행 결과 창 확인
  6. Esc — 다시 코드로 복귀

처음에는 어색하겠지만, 이 흐름이 손에 붙으면 마우스에 손을 올릴 일이 정말 드물어진다.

마무리

이번 편에서는 커서를 옮기는 다양한 방법을 살펴봤다. 정리하자면 이동의 단위를 계단식으로 넓혀가는 이야기였다.

글자 → 단어 → 줄 → 페이지 → 파일 → 문법 구조 → 도구 창

그리고 여기에 두 가지 규칙만 기억하면 상당수의 단축키를 유추할 수 있다.

  1. 이동 단축키에 Shift를 더하면 선택이 된다.
  2. 맥의 command/control이 윈도우에서는 Ctrl로, 맥의 option은 윈도우의 alt로 대응되는 경우가 많다.

이번에도 단축키가 많이 나왔으니 우선순위를 매겨보자면, 아래 다섯 개부터 손에 익히는 것을 추천한다.

  1. 단어별 이동 (option/Ctrl + ←→) — 방향키를 연타하는 습관을 없애준다.
  2. 범위 확장 (option + ↑ / Ctrl + w) — 마우스 드래그를 대체하는 가장 강력한 기능이다.
  3. Esc로 에디터 복귀 — 마우스 사용을 극적으로 줄여준다.
  4. 마지막 편집 위치 (command/Ctrl + shift + backspace) — 한 번 맛보면 못 끊는다.
  5. F2 → option + Enter — 오류 처리 속도가 달라진다.

그리고 CamelHumps 설정은 지금 바로 켜두자. 이건 외울 필요조차 없이 기존 단축키를 더 좋게 만들어주는 설정이다.

다음 편에서는 검색을 다룬다. 지금까지는 "보이는 곳으로 이동하는" 방법이었다면, 다음은 "어디 있는지 모르는 것을 찾아가는" 방법이다. 파일 이름도 기억 안 나고 어느 패키지에 있는지도 모르는 클래스를 몇 초 만에 찾아내는 방법들을 알아보도록 하겠다.
